JARVIS 管家 Worker Skill 与图书管理员架构设计
v1.5 管家控制面补充版
日期  2026-11-17    状态  架构修订稿    验证基线  Codex CLI 0.168.0 / 本地 Windows 环境
本版在管家 Agent、临时执行 Worker 和 Skill 能力库的基础上，恢复图书管理员为独立离线 Agent。图书管理员不向 Worker 提供在线检索接口，而是手动触发后整理历史 Session，维护 Obsidian 主题知识和任务经验注册表；管家在规划阶段读取注册表，把相关经验写入 Worker 的上下文包。
任务经验首版采用“已闭环 / 有待完善”两态。状态由图书管理员给出建议，人工复核确认。注册表先按任务调用频率降序排列，同时补充稳定任务标识、目标说明、证据、适用范围和 Skill 版本关联，避免任务名称变化或经验缺少依据。
v1.5 补充管家 Agent 的控制面定义。管家不再只是任务入口和调度者，而是任务闭环所有者：它负责把人类意图转化为可验收的闭环，规划所需 Skill、Worker 和上下文，基于证据推进或停止探索，并在授权边界内自主重规划。

排序规则
首版按任务调用频率降序排列；调用频率相同时，按最近更新时间降序。频率排序用于快速识别高频任务经验，后续再根据真实使用情况增加相关度、最近验证时间和成功情况等因子。

十一 结论
图书管理员作为独立离线 Agent 有必要保留。它在 v1.5 中不提供在线接口，而是维护 Obsidian 主题知识和任务经验注册表；管家在规划时读取注册表，再将经验写入 Worker Context Pack。首版采用人工复核状态和调用频率降序排序，同时补齐稳定标识、证据、适用范围和 Skill 版本，能够以较低复杂度落地。

附录 A 管家 Agent 控制面职责
管家 JARVIS 是长期任务闭环所有者与控制面。它接收人类伙伴的任务，定义目标、验收标准、证据要求和停止条件，规划所需 Skill、Worker 和上下文，组织执行并依据证据决定继续、重试、重规划或停止。
管家拥有规划和调度权，但不包办所有执行。它不能自行扩大权限、修改长期规则、批准自己的长期能力变更，也不能把候选经验直接升级为可信知识。

能力规划
管家的能力规划不是任意创建 Agent，而是在已有能力和候选能力之间做最小充分选择。
已有 Skill 能完成时，不派生 Worker。
需要上下文隔离、并行、独立复核或独立生命周期时，派生临时 Worker。
Worker 角色优先级为：通用角色模板 → 项目角色配置 → 新角色候选。
新 Skill 或长期 Agent 只生成候选，必须经过回放、人工确认和版本发布。
图书管理员经验作为规划输入；Worker 不直接访问图书管理员。

自主探索约束
自主探索不是无限制试错，而是围绕明确假设和证据阈值推进。管家必须记录探索假设、分支、预算、证据和收敛判断；当分支没有新增信息、超出预算或触碰高风险边界时，应停止并请求人工决策。
架构定义
管家 JARVIS 是长期任务闭环所有者与控制面。它接收人类伙伴的任务，负责澄清目标、定义验收与停止条件、设计任务图、选择或提出所需 Skill 与 Worker、装配 Context Pack、组织执行、观察证据、决定继续或重规划，并将任务经验提交给记忆与演进流程。管家不包办所有执行，也不拥有自行扩大权限、修改长期规则或发布可信知识的权力。
