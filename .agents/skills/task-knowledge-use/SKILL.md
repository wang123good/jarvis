# Task Knowledge Use

Work in the JARVIS project and read `docs/task-knowledge.md` for the current procedure. The parent task owns the authorized scope, its decisions and its evidence.

1. Name the decision or check that could change. Choose project, topic, or reference knowledge based on the question. Use the project's resolved environment and an authorized scope for every query. If there is no meaningful decision or the applicable sources are unavailable, continue the underlying task and record a relevant gap.
2. Read the original before adopting it. Determine its status, assumptions, currency and links to actual evidence. Check any material conflict against the present task and current source of truth. Treat an unverified note as a lead and use current evidence to confirm it.
3. Translate the material into an action or acceptance check. Record the decision, note and content fingerprint, applicable conditions, selected action and observed result in the parent task. When another agent performs the action, provide only the evidence and constraints it needs.
4. If an action needs a Skill, use the host's catalog or exact local lookup. Read the actual file and verify that its useful scope matches the task. When it is missing or ambiguous, identify a candidate with its source, required access and a replay case. Follow the project's review rules before acquisition or enabling.

After verification, keep only findings that could change a later task. State the conditions that would invalidate them and link the source evidence. Use the parent task's authorized knowledge closeout procedure.
