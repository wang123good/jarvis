# JARVIS 管家 v0.1 使用说明

本版是 `D:/codex-project/JARVIS` 项目主会话的角色指令配置。2026-11-18 用户授权“按建议落地”，入口为项目根目录 `AGENTS.md`；详细职责保留在 `架构方案/JARVIS 管家Agent职责定义 v0.1.md`。

## 首要职责与控制面

2026-11-18 用户批准控制面建议并强调意图理解为管家首要职责，已同步职责定义、AGENTS.md 与任务模板。执行顺序是：理解用户任务意图 → 识别并询问关键问题 → 形成可执行、可验收的任务契约 → 组织执行 → 按证据复核交付。简单任务直接完成；复杂任务简述理解和验收，不对已明确的授权重复确认。控制面仍为指令与文件约定，本次未验证自动恢复、强制隔离或硬预算。

## 如何使用

在本项目中直接提出工作任务即可，例如：“JARVIS，请评审这份技术方案，给出实施建议和不确定性。”简单任务直接完成，复杂任务由管家维护一份任务卡。无需为普通任务新建 Agent 或输入角色长提示。

建议下一次在此工作目录启动新会话，并先要求其说明读取了哪些项目指令，再给出真实任务。本次已明确读取新入口并执行首项试用；新会话自动加载及行为效果仍需实际观察，不能以文件存在替代验证。

- `jarvis/user-profile/`：2026-11-18 已获批准的项目级协作画像试点，含 P1—P3 来源引用、候选、发布记录及只读校验工具；使用与修订见该目录 README。跨会话应用效果待真实任务验证。

- `jarvis/knowledge-administrator.md`：已启用的知识库管理员职责、预检、整理与批准变更流程。
- `jarvis/knowledge-run-request.template.json`：每次手动运行的请求模板，填入明确来源、目标、读写范围和预算后使用；模板本身不可直接执行。

- `jarvis/worker.md`：已启用的通用临时 Worker 角色与管家派发规程。

- `AGENTS.md`：身份、工作顺序、权限和交付约定。

- `jarvis/defaults.json`：供管家读取的项目软默认值，不是 Codex 原生配置，不会自行执行限时或控费。

- `jarvis/task-template.md`、`jarvis/tasks/`：单份轻量任务记录与实际交付。

- `.codex/obsidian-kb.json`：现有知识库入口；正式经验与草稿保持区分。

当前采用直接/委派/探索三种模式，默认直接；临时 Worker 仅在实际可调用且已授权时按需使用。未注册命名子代理，不增加常驻进程、调度器或付费 API，不更改宿主沙箱、模型和审批设置。

2026-11-18 用户授权落地通用 Worker。你只需继续向管家提出任务；管家判断是否需要委派，组织工作包、派发、复核及关闭实例。W1 已验证单个临时 Worker 执行链路，本次接入可复用指令与模板；多 Worker 并行、硬隔离和成本收益仍未验证。

## 知识库管理员怎样使用

例如：“知识库管理员，整理当前会话中管家和 Worker 的职责设计，按主题生成草稿，先不正式入库。”管家明确限定本次来源并发起一次离线整理；只有来源不清楚才询问。正式写入时需复核具体差异，不能以落地角色的授权代替后续变更批准。

运行请求与报告放 `jarvis/knowledge-runs/RUN-ID/`。主题笔记和任务经验分开处理，旧目录 `50_图书管理员` 保留以兼容来源、模板和链接。无自动定时任务、不全量扫描、不向 Worker 提供实时检索。

本次接入仅验证文件与配置；没有因安装角色而导出会话或写正式经验。独立整理质量、完整增量和多文件恢复仍需一次明确触发的真实整理验证。

本角色接入前的入口、默认值和说明备份在 `jarvis/backups/knowledge-administrator-deployment/`；回退前核对后续人工修改，不触碰知识库正文或原始来源。
