## 实际行为

- sync默认business模式；prepare只读取指定线程，向知识库外的工作区生成来源绑定的复核清单。已识别的宿主角色/注入前缀省略；用户业务要求及纠正保留。助手消息进入pending，由整理实例判断实质性，逐项给出keep/omit及理由。pending或未知注入前缀不强行导出，也不退回全量模式。
- 必要工具证据只能是实际工具输出记录的精确摘录（最多4000字符），保留记录号和输出摘要哈希；未选入工具证据时明确说明助手陈述尚未获得独立核验。
- business只写业务对话页、筛选records.json、coverage.json和独立索引/manifest；source.jsonl、desktop.json及工具调用参数不复制。源SHA-256与选择/策略export_hash分开记录。记录页明确标注筛选及缺失范围，不冒充完整历史。
- --mode forensic或plan.mode=forensic显式进入原完整取证流程，沿用旧manifest、目录和来源组合哈希。verify默认识别两类既有清单，亦可指定模式；业务verify检查文件、记录身份、覆盖和渲染一致性，不证明源陈述真实。
- 原来源或语义选择改变生成不同版本；相同已校验输入不改写（包括mtime）。人工编辑冲突在本项目批次写入前拒绝；旧完整档案及其索引/manifest不被业务导出修改。
- 业务写入保存逐文件journal；部分失败后阻止未检查直接重放。检查真实文件和manifest后可由调用方声明resume_after_inspection=true，原失败journal按哈希留存。该字段是调用方声明，不证明检查实际完成；无跨进程锁、无多文件原子事务。
