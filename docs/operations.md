# JARVIS 使用与操作入口

JARVIS 在本项目主会话中理解意图、维护任务契约、组织执行并复核交付。项目规则入口为根目录 `AGENTS.md`，发布版本见[发布规则](rules/release.md)；角色初版 v0.1 不等于项目发布版本。当前实现依靠指令、模板和本地文件，宿主提供实际工具。

## 提出任务

直接说明问题和预期成果，例如：“JARVIS，请评审这份技术方案，给出实施建议、验证方法和不确定性。”

任务边界和执行意图明确时默认持久建卡、完整闭环，简单任务可简卡。先核对具体授权与契约，已有明确执行授权时连续执行、检查和修复，不为普通内部步骤重复请示；关键授权缺口才提交事前复核。复杂度决定记录与验证深度，委派单独按收益判断。具体关卡、例外、停止和验收规则见 `AGENTS.md`，不在此重复维护。默认直接执行，按需采用委派或探索模式；不必为普通任务新建 Agent 或输入角色长提示。

## 按需读取

只有唤醒且意图不明时才询问聊天或任务；明确任务直接形成契约。真实新任务默认规划专属聊天，用户明确授权新建聊天并符合宿主要求后，用正式工具在所属项目创建专属对话，按 E11 命名，回读并绑定任务卡；已有任务及交接接收方复用绑定，业务执行仍须事前复核。明确执行任务默认在 `.local/tasks/<task_id>/contract.md` 留卡；缺聊天授权不阻塞当前聊天中已授权的安全执行。

规划先记录并审查各步目的/产出用途，删去无价值步骤。中断后可直接说“JARVIS，恢复任务 <task_id>”或提供卡片路径；核对真实执行、产物、授权和剩余预算后接续，不清零重试、不重放未知副作用。完整运行步骤见 [任务闭环规程](task-lifecycle.md)。

| 文件 | 用途与触发条件 |
| --- | --- |
| `AGENTS.md` | 管家身份、事前复核、权限、清理保护及读取路由 |
| `config/defaults.json` | 本次预算和路径的软默认值；不是 Codex 原生配置 |
| `docs/task-lifecycle.md` | 任务识别、规划价值审查、环节记录、人工恢复、收尾与 Skill 判断；涉及这些动作时必读 |
| `templates/task.md`、`.local/tasks/` | 明确执行任务默认留卡，按复杂度简写或完整记录契约、检查点与验收 |
| `agents/worker.md`、`templates/worker-work-package.md` | 有明确委派收益且宿主支持时，定义角色与本次工作包 |
| `agents/knowledge-administrator.md`、`templates/knowledge-run-request.json` | 手动整理或任务契约已批准的验收后收尾；限定来源、目标、读写范围及预算，占位模板不能执行 |
| `docs/user-profile.md`、`up.example.json` | 画像读取和安全维护；实际数据仅在根目录 `up.json`，不提交 Git |
| `.local/environment.json`、`config/environment.example.json`、`scripts/setup_environment.py` | 本机绝对路径、可分发示例与首次配置入口；实际配置不提交 Git |
| `.codex/obsidian-kb.json`、`scripts/resolve_environment.py` | 共享知识层级、统一路径解析；写库前核对连接实际路径，规则见 I01 |
| `docs/environment.md` | 环境准备、现行目录、命名、模板、初始化及迁移 |

画像首次仅询问昵称，可跳过；明确保存的偏好按画像规则维护，观察候选确认后生效，旧画像不自动迁移。

## Windows 命令执行与 shell 选择

在 Windows 上调用 `exec_command` 前，先按命令语法选择 `shell`：

| 命令内容 | `shell` | 说明 |
| --- | --- | --- |
| PowerShell cmdlet、`$env:` 变量或 PowerShell 管道/引号 | `powershell` | 不要送入 `bash` 或 `cmd` |
| cmd 批处理语法，例如 `%VAR%`、`dir /b` | `cmd` | 仅用于 cmd 语法 |
| Bash/POSIX 语法 | 先确认 Bash 可用且实际被选择 | 若 `bash` 回落到 `cmd.exe`，不得把 `shell=bash` 当作 Bash 语义 |
| 普通可执行文件且无 shell 专有语法 | `powershell` | 路径和参数仍按 PowerShell 规则引用 |

执行前检查：

1. 命令出现 `Get-*`、`Set-*`、`$env:` 或 PowerShell 管道/变量时，选择
   `powershell`。
2. 命令出现 `%VAR%` 或 cmd 专有参数时，选择 `cmd`。
3. 需要 Bash 时先做只读探测，确认实际 shell；发生回落时停止并改写命令，
   不重放相同调用。
4. 含空格或中文的 Windows 路径在 PowerShell 中使用单引号；不要把
   PowerShell 双引号中的 `$` 当作普通字符。
5. 命令未执行或路径中出现字面 `$env:` 时，保留退出码和错误，标记“未执行”，
   再用匹配的 shell 重跑原意图。
6. 单独核对引号、路径和变量展开，不把它们都归因于 shell 选择。

该检查是操作规则，不是宿主级拦截。执行结果仍须用退出码和实际输出验证。

## 知识收尾与手动整理

任务交付时默认在本任务 closure/ 生成三层本地待复核材料：任务总结、wiki 候选、过程归档，并集中列出每项风险、证据缺口及建议结论。任务总结记录目标、结果和验收证据；wiki 只提炼有来源的可复用结论、条件和反例，无新增知识则记“无候选”及理由；过程归档保存必要业务要求、关键决定、有效发现、失败路径与来源覆盖，不保存宿主噪声或冒充完整逐字聊天。三层是覆盖检查，不要求三篇重复笔记。业务交付前可准备候选，状态不因此变成用户已验收。

用户明确“不整理”时跳过笔记，限定层级时按该选择执行；已有任务的明确选择继续有效，旧卡未授权的策略不追溯改写，恢复旧任务时按其契约处理。仅说“不入库”表示禁止写库，按本次默认策略仍可准备本地候选；若语义还限制本地整理则从其明确范围。无需重复询问一般笔记选项，不把沉默当作复核通过。

业务验收与笔记复核分别记录。业务未验收时标“已交付待验收”，并列笔记状态；业务已验收或明确无需人工验收而候选待审时标“已交付待笔记复核”。用户复核可接受、退回或明确跳过；接受本地候选不批准正式写库，不自动提升知识状态。风险复核表使用 templates/task-closure-review.md；可用 scripts/task_closure.py 只读核对来源/产物哈希及状态，它不判断语义质量，也不写库。

正式写库须另有具体目标、来源白名单、内容差异、预算、基线及冲突处理批准，并验证当前实例选定库；未批准只交本地候选。无全库扫描、日报周报、自动发布或删除授权。覆盖 wiki、正式经验和长期 Skill/Agent 仍须对应差异批准。

收尾时依据当前需求、已确认相关喜好/职责、目标输入变化和维护收益判断 Skill；职责未知不推断，偶发/探索任务可不固化，也可只固化局部或判断方法。集中报告理由，有价值才询问制作；不做不阻塞关闭。

例如：“知识库管理员，请整理当前任务的方案决策与验证结论，生成候选草稿供我复核。”

管家明确本次来源和目标；可从当前任务唯一确定的范围直接列明，确有歧义才询问。运行请求和报告保存在 `.local/knowledge-runs/RUN-ID/`。默认先交候选及 diff，正式写入需对应批准与基线核对，角色启用授权不能代替变更批准。

当前采用草稿／工作记录／wiki 布局，对话为 `06 归档` 下的扁平 Markdown；详细规则见环境说明。历史 `50_图书管理员` 名称仅保留来源与链接含义。整理不自动触发全库扫描、定时任务或向 Worker 提供实时检索；“清理聊天且不整理笔记”按入口清理规则执行。

## 接入检查与回退

首次接入显式选择当前实例的目标库；外部连接器的实际路径另行核对，不能用它静默替换实例目标。文件入口运行：

```powershell
python scripts/setup_environment.py --vault "用户选定的知识库绝对路径"
```

该入口只写本机环境文件和本地解析指针，不改画像或共享配置。旧版配置先按环境说明预览并确认迁移。使用 external 连接器时额外传工具实际报告的 `--connector-vault`，与 `--vault` 分开；CLI 使用前另运行 `scripts/obsidian_cli.py` 核对 PATH 和真实目标。随后运行：

```powershell
python scripts/verify_installation.py --environment-only --connector-vault "工具报告的知识库绝对路径"
```

脚本在 `.local/verification-runs/` 排他创建独立目录，保存报告和被测哈希；可用 `--run-id` 指定新 ID，已存在则拒绝。上述命令只检查资源、本机配置和连接路径；省略 `--environment-only` 才检查真实注册表及限定检索，要求外部检索工具支持全局 `--config`。工具报告的库路径须先实际读取，不能猜测。检查不验证意图理解、完整恢复、跨会话复用质量或所有规则行为。

历史证据已迁往仓库外，路径映射见 [归档索引](archive-index.md)。以下均为原归档路径：首轮试用见 `jarvis/tasks/JV-20261118-001.md` 及同名 `-verification.json`；单 Worker 链路见 `experiments/W1/steward-recheck.json`。这些结果仅对当时输入有效，不证明多 Worker 并行、硬隔离或成本优势。

回退前保留当前差异，核对后续人工修改；以下备份按归档索引定位，原入口见 `jarvis/backups/initial-deployment/AGENTS.pre-deployment.md`，管理员接入前备份见 `jarvis/backups/knowledge-administrator-deployment/`。不覆盖后续修改、不触碰知识库正文或原始来源。

## 实现边界

Worker 和管理员按需运行，依赖宿主实际能力；收尾按工具完成或停止，无销毁工具不声称已销毁。未注册长期命名子代理，不增加常驻进程、调度器或付费 API，不更改宿主沙箱、模型或审批。软预算、职责分工和恢复规程不构成系统级限额或隔离。

新会话自动加载和实际遵循效果须另行观察；文件存在、接入检查通过不等于行为已验证。机制参考：[官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)，不能据此推断未实现能力。
