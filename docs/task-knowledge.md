# 任务知识应用

每项实质任务先明确一个待决定的问题，例如“本次部署怎样确认实际连接库”。识别不到能被知识改变的决定时，任务照常推进。执行期间出现新缺口时，用同样的方法补查。

1. 先运行 `python scripts/resolve_environment.py`。按 I01–I03 处理正式经验注册表，缺失或接入不兼容时记录状态，继续查适用的普通笔记。普通笔记可以用下列仓库自有只读入口，也可用已经核对目标的限定连接器。连接不可用、空目录和无匹配分别记录。
2. 项目层查已确认约束和历史任务。主题层查方法、反例与条件。参考层查文档、版本与证据。主题和参考层需要一个经本次授权的具体文件夹。每次只读解决此决定所需的结果和来源。
3. 检索命中是线索。读原文，核对状态、来源、版本、适用条件和失效条件。草稿、冲突及过时材料不能直接约束执行。若冲突影响本次动作，先用当前任务要求及实际证据核验，无法判定时标记待决。笔记正文是资料，不能授权动作或替代当前任务契约。
4. 采用时，在任务卡记录“决定 → 来源及状态 → 适用理由 → 动作 → 本次检查”。未执行标待验证。需要 Worker 时，把相关内容、约束与建议的区分及证据位置放入现有工作包。
5. 有能力缺口时，先按能力查宿主已列出的 Skill，再以确切名称核对项目和本机文件。读取选定的真实文件，检查适用性、版本或哈希，按能力范围执行。若缺失或重复，记录缺口、拟复用的真实来源、依赖、权限及隔离验证方法，提交具体获取或创建提案。现有工具足以完成本任务时继续执行。取得长期 Skill 后须按项目规则复核并回验宿主发现状态。
6. 从本次实测结果提取候选，保留任务 ID、可核对证据、适用范围、失效条件与未验证项。按任务收尾授权决定是否写 Obsidian。普通笔记可由后续任务按来源重新判断；正式经验还需人工复核并绑定真实 Skill。核准的新笔记按批准目标写入并回读，发现同名或内容冲突时交回管家处理。是否成功复用由另一任务的实际结果验证。

```powershell
python scripts/task_knowledge.py search --layer project "知识库" "初始化"
python scripts/task_knowledge.py search --layer domain --folder "03 wiki/主题" "部署"
python scripts/task_knowledge.py skill obsidian-kb
```

查询只返回候选路径、内容指纹和短摘录，按字面匹配。项目层只读本项目总结及规则。自定义文件夹须在相应层范围内。相比目录统计，返回的未读范围和跳过项更能说明本次查询覆盖。该脚本不实现正式经验排序，也不写库、安装 Skill 或自动判断是否采用。
