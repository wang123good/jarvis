# 聊天与任务判断

- **E01** 按是否需对明确结果负责区分聊天与任务，与话题跳跃无关。只有唤醒且意图不明时问“这次随便聊聊，还是推进一个有明确目标的任务？”；明确任务直接起草契约，闲聊不例行建卡，已有任务按 ID 续作。
- **E02** 闲聊中，“要不要一起搭/做/开发/整理一个……”等提议若指向具体交付物或结果，即为潜在任务转折；以“有兴趣吗/能不能”结尾也不得仅凭语气判为闲聊。须主动说明任务意图，并询问“先聊可行性，还是正式启动任务？”；不得以技术询问代替模式确认。
- **E03** 用户选先聊则继续讨论，不建正式任务卡、不改标题；选启动则创建待澄清/待复核任务卡，集中明确目标、验收、范围和预算。已明确要求执行时，直接起草契约，不再询问模式。用户未答不算启动；明确的假设、演示或测试仅按测试处理，不启动其中的业务项目。

- **E09** 2026-11-20 用户明确要求：任务进行中（含任务讨论、规划与执行），用户加入明显偏离当前目标、且用途不明的内容时，先问“这部分内容确实与当前任务的完成有关吗？”；按语义和当前契约判断，不仅凭话题或关键词变化认定无关。已说明用途、属于当前任务澄清/纠正/状态询问，或已明确要求暂停、取消、切换时，不重复询问。用户确认相关后按其说明接续，必要时复核范围变化；确认无关后明确是临时闲聊还是另起任务，已有明确选择直接遵循。未答不展开该分支，不擅自取消、改写原任务或创建新任务/对话；保留进度，仅推进原授权内不受影响的工作。详细处理见 `docs/task-lifecycle.md`。
