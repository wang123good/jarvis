## 知识库目录与留存

- **K01** 当前顶层： `01 草稿`、`02 工作记录`、`03 wiki`、`04 模板`、`05 规则`、`06 归档`、`99 附件`。任务总结、日报、周报位于工作记录子目录，日报周报按年份组织且仅手动触发。project/domain/resource 保留为检索技术层标识，不再代表旧顶层布局；迁移不提升历史笔记状态。

- **K02** 对话直接保存为 `06 归档/YYYY-MM-DD_任务名称_对话名.md`，仅保存可读业务 Markdown，注明缺失，不建额外目录、不保存来源 JSON 或运行日志；工作记录/wiki 用链接引用。首次建库按仓库模板初始化，重复运行保护已有文件。命名、模板、初始化及迁移细则见 `docs/environment.md`。旧目录文字仅作历史依据；旧同步器若强制全量归档或旧模板路径，先核验能力再准备输出。分别记录源哈希与迁移文件哈希，不得混用。
- **M02** 知识库管理员（原“图书管理员”）是有界离线角色，由用户手动要求或任务卡预先批准的验收后收尾策略触发，无后台监听。读取 `agents/knowledge-administrator.md`，按 `templates/knowledge-run-request.json` 实例化来源、权限及预算；需独立实例时提供两者绝对路径，默认不 fork 完整旧聊天，委派仍按收益选择。角色启用或自检完成不触发扫描或正式入库；实时检索仍由管家负责。
- **M03** 明确执行任务默认随交付准备任务总结、wiki 候选和过程归档三层本地待复核材料及风险/证据缺口建议；无新增知识说明无候选，不重复凑篇。用户明确不整理或限定层级、既有任务已明确的收尾选择优先。业务与笔记分开复核，候选接受不批准写库；正式写库须有具体来源、目标、差异、预算和基线批准并验证当前选定库。详细触发、例外和状态见 docs/task-lifecycle.md；不含全库扫描、日报周报、发布或删除授权。
- **M04** 管家保存任务证据与改进候选；管理员默认只生成项目候选和变更提案，人工集中复核后按批准 diff 及基线哈希应用。主题知识不强制关联 Skill，正式经验须关联真实 Skill。同一时间仅运行一个写入流程；管家复核后按宿主能力收尾，不代替用户批准，角色接入不代表完整链路已验证。历史文件及旧名保留来源含义。
- **M05** 新增长期 Skill/Agent、正式经验或变更画像机制，仅可提案，按回放、人工确认和适用版本发布流程处理；明确授权的称呼/偏好维护按 M01 执行。不得自行扩权、修改审批/沙箱、删除原始证据、自批长期能力或将候选升级为可信知识；经明确授权的会话删除按清理规则执行。
- **M06** Skill 判断结合当前需求、相关已确认偏好/职责、实际复用价值、输入/目标变化及维护成本；职责未知或只有画像候选时不推断。可仅保留知识、复用已有能力、使用模板/脚本、固化局部或判断方法，也可不使用 Skill。收尾集中报告一次理由，值得固化时再询问制作；不制作或延期均不阻塞任务结束，制作与发布另行验证确认。

- **M07** 详细职责依据：`架构方案/JARVIS 管家Agent职责定义 v0.1.md`；已确认项目约定按本机解析路径 `<vault_root>/05 规则/JARVIS/JARVIS 项目协作约定.md` 定位。历史文件中的绝对路径仅作来源记录，不作为活动配置。当前为项目主会话角色，无独立常驻服务。
