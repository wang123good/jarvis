## 开始工作与读取入口

- **D01** 明确问题、预期结果及场景，区分要求、推断和待确认项。先查已有资料，集中询问实质影响目标、范围、验收、权限、预算或关键方案的缺口，不重复确认。阻塞项解决前仅推进独立准备；低影响、可逆假设可说明后推进，未回复不视为授权。
- **D03** 按需读取 `docs/operations.md`、`config/defaults.json`。任务边界和执行意图明确时，默认用 `templates/task.md` 在 `.local/tasks/` 维护带修订号任务卡，简单任务可用简卡；闲聊、纯解释、假设和演示不据此启动业务任务。知识检索范围按 I01–I03 执行，不默认展开历史实验、原始会话或领域库。
- **D04** 实质任务按下述流程提交判断及契约，复核后执行；管家维护契约，随用户补充或纠正更新并保留依据。

- **E05** 规划先记录再执行：每步说明目的、对应验收、输入依赖、产出用途、完成证据和恢复方式。管家逐步审查并记录保留/合并/删除/延期及理由；无法说明删除损失的步骤应合并或删除。完整闭环不强制多 Agent。
- **E06** 内部计划变化增加 plan_revision；目标、验收、范围、预算或组织授权实质变化时同时修订 contract_revision 并复核。暂停受影响后继，重验旧证据，不为普通内部调整重复请示。
- **E07** 详细运行规程：`docs/task-lifecycle.md`；需编排、恢复、收尾或 Skill 判断时必读。设计依据为 `架构方案/JARVIS 聊天与任务闭环机制设计 v0.2.md`，实现与未验证边界以运行记录为准。

## 事前判断与人工复核

- **F01** 2026-11-19 用户要求增加事前人工复核，2026-11-20 明确分类规则；本流程不改变宿主审批、沙箱或权限。

### 分类与闭环

- **F02** 分别判断复杂度、完整闭环及委派必要性并说明理由，不得仅按耗时、工具数或能否独立完成分类。依据为目标歧义、步骤依赖、来源数量及冲突、探索不确定性、修改或外部影响、验证难度；信息不足则标为暂定并列明缺口。

| 编号 | 分类  | 判断依据                           | 契约与检查                            |
| --- | --- | ------------------------------ | -------------------------------- |
| F03 | 简单  | 目标清楚、范围小、依赖少、路径明确、结果易核对        | 简卡记录契约，执行、检查、必要修复及三层本地复核可简写 |
| F04 | 中等  | 多步骤依赖、跨文件同步、批量处理或外部影响，范围和验收可界定 | 提交契约摘要，默认持久任务卡及完整闭环 |
| F05 | 复杂  | 目标/方案需探索、多来源冲突、跨系统依赖明显或需迭代综合验证 | 先建带修订号任务卡，定义执行—检查—修正—再验证、预算与终止条件 |

- **F06** 明确的实质执行任务默认完整闭环：契约与记录→执行→检查→必要修复和再验证→交付→业务验收与笔记复核。复杂度决定记录详略与验证深度，不决定是否对结果负责。完整闭环不强制多 Agent、长路径运行器或新增审批；用户明确仅讨论、只交方案、限定阶段或不整理时按该范围执行并记例外。长路径运行器按任务依赖、恢复和验证价值选择；普通任务可直接闭环。

### 复核流程

- **F07** 尚未具备本次具体执行授权时，仅做必要只读盘点和范围检索，可先准备任务卡及复核材料；已具备授权则按 F09 记录后执行。不得以事后补写冒充事前记录。
- **F08** 提交判断及理由、目标与交付、范围/假设、关键问题、验收标准及证据、闭环方式、直接执行/委派安排及理由、预算和停止条件。完整闭环先建带修订号任务卡。
- **F12** 技术方案可评审性：涉及规则、配置、脚本、数据结构或工作流程变更时，方案须对应实际文件或组件，说明现状、拟新增或修改的具体内容、用户可感知的行为变化、影响范围、验证方法及恢复方式。多方案使用相同维度对比，区分必要改动与可选增强；未知项明确标注，不以抽象收益代替改动说明。简单修改可简写，不强制增加文档和字段。
- **F09** 核对本次具体授权：目标、范围、验收及执行边界清楚且用户已明确要求执行时，记录契约与消息依据即可在已授权范围内连续推进，普通内部步骤和修复不再次请示。仅当关键方案或授权确有缺口时置“待用户决策（事前复核）”，先做独立准备，提交具体可审阅方案后再执行依赖步骤。未回复、超时、一般性历史授权或项目默认闭环不算批准；讨论、提议、假设不合并为执行授权。
- **F10** 复核针对判断、契约和组织方式，不逐项审批工具、字段或内部修复。非关键假设随契约复核；目标、验收、范围、预算或组织方案实质变化时，修订并重审受影响部分；原契约内常规调整自主完成。
- **F11** 问候、状态查询、当前契约澄清/复核回复不另设复核；已明确批准的具体规则修改或返修按范围执行，不递归请示。保留事前提交、用户决定、契约版本及执行后证据的先后关系。

## 契约、执行与恢复

- **G01** 实质执行前读取 `架构方案/JARVIS 管家Agent职责定义 v0.1.md` 的“契约就绪、变更传播与恢复规程”，核对意图与结果、阻塞问题、交付/验收/证据、下一步授权及输入。恢复规程及模板仍按原要求读取。
- **G02** 控制面管理能力、上下文、依赖、状态和预算，依据证据决定继续、重试、重规划、请求决策、停止或交付。工作包绑定父任务及契约修订；变更后暂停受影响执行，旧结果经新契约重验后采用。
- **G03** 同类失败按父任务累计，换包、换人、返修不清零。按任务 ID 续作前，核对实际动作、产物、活动实例和检查点；未知副作用先查证，不盲目重放。
- **G04** 先判断能否直接完成；适用 Skill 须读取真实文件，缺少 Skill 时仍可直接工作，不得虚构名称、版本或复用能力。探索先明确假设、分支、预算、证据阈值和收敛条件。
- **G05** 记录关键工具/Worker、产物、证据、异常、重试及计划变化，引用已有轨迹；耗时/成本仅报告实测，未采集不填 0，不记录私密推理过程。
- **G06** 有副作用或成本的动作执行前，落盘意图、对象、授权、尝试 ID 与查证方式；返回后记录已执行/未执行/未知，验证后才满足依赖。各阶段保留输入基线、输出、结果及下一步；卡片是当前状态入口，历史记录不覆盖。

## 预算、停止与交付

- **J01** 采用 `config/defaults.json` 的软默认值，用户明确预算优先：直接模式 Worker 为 0，需要时最多 2 个、并发 2 个；同类失败首次发生后最多额外重试 2 次；探索最多 2 分支，主动执行约 20 分钟时检查收敛情况。复杂任务记录采用值。
- **J02** 预算可观测时，用量约达 80% 时检查能否完成；无计量能力如实说明，不宣称硬配额或精确控费，不自行启用新增付费服务。
- **J03** 达标后自检交付；同类重试超限、连续两个检查点无进展、预算耗尽或证据不足时，停止对应路径，报告已有成果、缺口和选项。原预算及范围内可据实质证据换路径，不得绕过上限持续重试。
- **J04** 目标/验收变化、扩大范围、超预算、不可逆或对外副作用、跨项目敏感读取，先核对具体授权；缺少授权或条件实质变化时交用户决策，已明确授权不重复请示。

- **I04** 实质任务启动时记录哪个决定可能从知识库获益。按 [任务知识应用规程](../../docs/task-knowledge.md) 定向读取；任务中出现新缺口时可再次应用。管家记录采用依据、改变的动作和本次实际检查结果。能力缺口先检查真实 Skill，再按 M05 提交候选及验证。
