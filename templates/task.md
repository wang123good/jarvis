# TASK-ID：任务名称

- 状态：待澄清 / 待复核 / 执行中 / 待用户决策 / 已暂停 / 已交付待验收 / 已交付无需验收 / 已验收 / 已取消 / 失败或停止（选择一项）
- task_id / contract_revision：稳定任务 ID / 从 1 递增；修订保留快照或精确差异及授权依据。
- plan_revision：计划修订独立递增。
- 对话绑定：source_thread_id（来源）、task_thread_id（专属对话）、project_id、task_thread_title（任务名称【当前状态】）；旧 session_ids 如保留，只作关联历史，不代表专属绑定。
- session_binding_status：待创建 / 创建中 / 已创建待核验 / 已绑定 / 阻塞 / 结果未知（选择一项）；creation_attempt_id、创建回执、标题/项目独立回读、接收确认及替代关系：
- 分流依据：用户明确建立真实新任务后首次建卡即创建专属对话；既有绑定任务复用。接收交接为续作，模板/测试/补录不触发；创建结果未知先查证，命名或关联失败修复已有对话。
- 交接包：按 templates/task-session-handoff.md 填写任务卡绝对路径、任务 ID、需求摘要、契约/计划修订、授权状态、待确认项、下一步及可读来源。建会话不构成执行批准，原对话保留。
- 验收方式：用户验收 / 无需人工验收（说明依据）；不因自检通过自动豁免验收。
- 用户意图：用户原始要求、要解决的问题、预期价值、使用对象及场景；不明项不推断为事实。
- 入口依据：明确执行指令 / 聊天中提议后确认启动 / 恢复旧任务；记录用户消息。仅提议、未回答或明确测试不视为业务启动；模式确认不等于完整契约已获复核。
- 用户目标与授权：可执行目标、已授权动作及依据。
- 关键问题与假设：区分已明确事实、低影响可逆假设、阻塞性待决问题；记录答案及影响，无则注明。
- 交付与验收标准：逐项对应“交付物 → 可核对的结果/质量标准 → 验证方法及证据”；探索任务写明探索边界与收敛证据。
- 范围及不做事项：
- 必要依赖：输入、前置条件及阻塞关系；无需复杂任务图时简记。
- 模式与能力：direct / delegated / exploratory；实际 Skill、Worker 及选择理由。
- 输入、经验与来源：路径及必要版本/哈希；无正式经验时注明。
- 知识应用（有影响时记录）：当前决定、来源及状态、适用条件/冲突、采用动作、本次检查结果。无需求或未找到可用资料可简记；能力缺口写明需要的能力及拟验证方式。
- 本次预算：主动执行上限、收敛检查点、截止时间、用户/外部等待边界、Worker 总数/并发、重试单位及上限、分支、费用边界；计量能力和未知项。不把检查点当总时限，恢复不清零。
- 停止及升级条件：沿用默认规则，任务特殊要求另记。
- 知识收尾：业务验收后先问一次笔记选择（不整理/仅本地/知识库）；已有本任务明确选择不重复问，记录消息依据。未答不自动生成笔记，收尾待选择；必要执行记录不受影响。仅同意本地时于 closure/ 准备总结与必要候选。知识库写入另明确触发、来源白名单、路径、可写字段/新增方式、预算、批准依据与冲突处理；未批准不写库；仅说不入库不自动视为同意本地整理。

## 关键执行与决策

记录契约变更及其用户要求/批准依据；实质变化先请求决策。只记关键动作、工具或 Worker、结果/异常及调整依据；引用已有工具证据，不复制整段轨迹。

## 验证、交付与限制

逐项填写“验收项 | 通过/未通过/未验证 | 证据定位”，必需项未通过不标完成。记录实际验证、产物路径、验收证据与未验证项；自检和用户验收分开。耗时/成本未采集时如实说明。

## 反馈与演进候选

用户反馈原意、可复用候选及状态；没有则注明无。不得在本卡内自行批准长期发布。

## 验收、收尾与关闭

- 用户验收：通过/退回/追加要求；原话依据、适用修订、遗留项及去向。自检不冒充验收。
- 收尾状态：未开始/准备中/待知识复核/已完成/明确跳过/已转交；本地候选及知识库实际写入分别列明。
- Skill 决策：无需/复用已有/模板或脚本/局部或判断方法/新 Skill/待证据；结合当前需求、已确认画像相关条目及来源、职责未知项、输入目标变化、复用收益、维护成本和适用边界；不推断画像、不强制 SOP。
- 用户对 Skill 的决定：不做/延期/另立关联任务；有价值时集中询问，不自动发布。
- 关闭检查：关联事项已验收/明确停止或转交、无活动执行或未知副作用、产物与恢复入口已交付、收尾已完成/跳过/转交、Skill 决定有记录。聊天关闭不授权归档或删除。
